## Как продолжать

- `[ ]` — не проверено / не сделано; `[~]` — частично; `[x] ~~текст~~` — реализовано и проверено, с записью проверки ниже.
- Старые отметки done не доказывают исправление нынешнего бага. Для визуальных задач нужна проверка в приложении; для памяти — измерения процесса, а не только heap.
- После каждого законченного изменения обновлять этот файл: зачеркнуть выполненное, записать файлы, проверки и ограничения, затем следующий шаг.
- Исходные номера сохранены. Повторные 63 и 64 обозначены 63-б и 64-б.
- На старте DLL уже была изменена; первый Gradle-запуск её пересобрал без предварительной копии. Позднейшее состояние сохранено в `scratch/safety-20261017-phase2` и git stash. В v1.4.3 upstream удалил tracked DLL: `compileNativeDSP` теперь пишет в `buildDirectory/generated/native-resources/native`. После нового checkout её НУЖНО собрать до тестов/упаковки. `-x compileNativeDSP` допустим только при наличии актуального сгенерированного DLL; иначе нормализация молча перестаёт работать. Старый stash не применять поверх новой JNI-библиотеки.
- Не заявлять достижение 300–400 МБ, превосходство автомикса или бесплатную генерацию ИИ без измерений/проверенного сервиса.
